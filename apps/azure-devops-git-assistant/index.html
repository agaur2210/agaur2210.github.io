About Azure DevOps Git Assistance

Azure DevOps Git Assistance is a Chrome Extension that adds productivity features directly inside Azure DevOps. Everything runs in your browser. No external server is involved except Azure DevOps and, optionally, AWS Bedrock.

Branch Toolbar

Features injected directly into the Azure DevOps branch list. No navigation required.

PR Creation

One-click PR creation

+ PR next to every branch. Creates a PR with title, description, and work items pre-filled. Inline Publish / Delete / View actions appear on success.

Draft mode

PRs are drafts by default. Toggle Create as Draft off in the popup to publish immediately.

Configurable targets

Set a default target branch (default: develop) and a separate one for develop source branches (default: main).

Auto-fill from branch name

Title and description generated from your branch name and commit history. Prefixes stripped, commits grouped by type. Merge commits and low-signal messages (wip, fix typo) excluded automatically.

Work item linking

Numeric IDs in the branch name (e.g. feature/12345/...) are linked to the PR automatically.

AI description generation

Connect AWS Bedrock to refine descriptions with AI. Disabled by default. Requires configuration in the popup.

Delete branch

Ownership-verified deletion

Delete button appears on your branches only, enabled once you are confirmed as the last committer. Inline Sure? confirmation prevents accidents.

Admin Delete

Enable in the popup to delete any non-protected branch regardless of ownership. Protected branches (main, master, develop, release) are always blocked.

Work Item Toolbar

Features injected directly into the Azure DevOps work item form toolbar.

AI Remediate

One-click AI fix

AI Remediate button appears in the work item toolbar. Clicking it prompts for project type, then triggers a configured ADO pipeline that uses an AI agent to investigate the work item, locate the root cause in the repository, apply a minimal fix, and open a Pull Request — all without leaving the page.

Live progress feed

A floating panel tracks the pipeline in real time: first showing pipeline task steps, then switching to an agent tool-call feed grouped by phase (Investigating → Planning → Remediating → Validating → Creating PR). Run state is saved locally so progress is restored after a page refresh.

  2. Click New Token

How + PR works

  1. Click + PR next to any branch name (excluding main / master)
  2. The extension derives a PR title from the branch name (strips prefixes, title-cases)
  3. The target branch is determined from your popup settings, defaulting to develop or main when your source is develop
  4. It fetches commits between your branch and the target, filters noise, and generates a structured description with Summary, Changes, and Testing sections
  5. Any numeric IDs in the branch name (e.g. feature/12345) are included as work item links
  6. If AI Description Generation is enabled and Bedrock is configured, the description is enriched before the PR is created
  7. The PR is created via the ADO REST API. The page stays the same with inline actions appearing immediately
  8. When Create as Draft is on: Publish, Delete, and View actions appear. When off: only Delete and View
  9. If no PAT is configured, session cookies are used automatically

How branch deletion works

Deletes the branch from the remote repository for everyone. This is equivalent to git push origin --delete branch-name.
  1. The Delete button is always visible next to non-protected branches, but starts disabled while ownership is checked
  2. The extension identifies you via the ADO identity API using your PAT, then enables the button if you were the last committer
  3. With Admin Delete enabled, the button is enabled immediately for any non-protected branch regardless of ownership
  4. Protected branches (main, master, develop, release/*) are never deletable
  5. Click Delete → an inline Sure? ✓ ✗ confirmation replaces the button
  6. Click ✓ to confirm. The branch is deleted from the remote and removed from the list

Expand Agent Budget Limits inside the AI Remediate configure block to cap how many resources the AI agent may consume per pipeline run. Leave any field blank to use the pipeline default.

Option Default Details
Max Fix Attempts 3 Maximum number of times the agent will attempt to apply and validate a fix before giving up.
Max Iterations 50 Total agent loop iterations across all phases. Prevents runaway agents on complex issues.

PAT scopes required for AI Remediate & AI Review In addition to Code: Read & Write, the PAT needs Work Items: Read & Write so the pipeline agent can read work item details and post the created PR URL as a work item comment.

How AI Remediate works

  1. Click AI Remediate in the work item toolbar — a project type picker appears (.NET or Node)
  2. The extension reads the work item title, description, and form text to detect the target repository (looks for Repo: org/project/repo-name). Falls back to Default Target Repo from popup settings if not found
  3. The git-helper-ai-remediate pipeline is triggered via the ADO Pipelines API with workItemId, targetRepo, and targetBranch as template parameters. Your PAT and Bedrock bearer token are passed as masked runtime variables so the pipeline agent can authenticate. Any configured Agent Budget Limits (max fix attempts, iterations, tool calls, wall time, input tokens) are also passed as pipeline variables
  4. A floating progress panel appears. It shows pipeline task steps while the pipeline starts, then switches to a live agent tool-call feed once the AI agent begins working
  5. The agent works through five phases: Investigating (reads code), Planning (forms hypothesis), Remediating (applies patch), Validating (checks fix), Creating PR (opens a pull request and links it to the work item)
  6. On success, a View Pull Request → link appears in the panel and below the button. On failure, a link to the pipeline run is shown instead
  7. Run state is saved locally — if you refresh the page while a fix is running, the progress panel is automatically restored and polling continues

⚠ backtick-execution (/`[^`]{5,}`/) is intentionally broad — work items with inline code like `StackOverflowException` will be blocked. Known limitation.

base64Guard always on

Detects Base64-encoded payloads that could smuggle injection patterns past the regex guard.

llmGuard optional

Secondary LLM evaluator. Active when llmClient is in GuardOptions.

azurePromptShield optional

Calls Azure AI Content Safety prompt shield. Requires AZURE_CONTENT_SAFETY_ENDPOINT + AZURE_CONTENT_SAFETY_KEY.

Length guard removed. The 8 000-char limit blocked legitimate large work items.

Output scanner

Runs on git diff --cached after every apply_patch / replace_in_file. On failure the file is unstaged and restored — patch rolled back.

Critic Phase

Independent LLM call (no tools). Receives fix plan + unified diff hunks via git diff --cached --unified=5 — up to 8 000 chars per file. A reject always blocks PR — no bypass limit.

DO evaluate

  • Does the fix address the root cause in the plan?
  • Are there logic errors, bypasses, or unintended side effects?
  • Does the change match acceptance criteria in the work item?
  • If a version number was replaced — does the old value still appear in patched content?
  • (Bug fixes only) Is a regression test present and does it cover the specific bug?

DO NOT reject based on

  • Whether a CVE exists in any external database (no internet access)
  • Whether a package version exists on NuGet / npm / PyPI
  • Whether a version bump is a breaking change
  • Any external fact not derivable from the provided text

PR Description — AI Generation

The + PR button generates an AI-refined description from commits and changed files.

  1. Fetch branch commits and changed files from diffs/commits API in parallel.
  2. Filter commits (merge commits optional per settings).
  3. Template generator builds structured draft.
  4. AI refinement receives draft + commit messages + changed file list — uses file paths to make bullets specific.
  5. Refined Markdown set as PR description on creation.

Logging

[plan] planText preview after PLANNING
[remediate] 0 patches applied warning
[proving] non-fatal proving failure
[reproducing] pre-fix test run result
[critic] full reject feedback

Privacy Policy

Last updated: September 28, 2026

Overview

Azure DevOps Git Assistance is a Chrome Extension that adds PR workflow features to Azure DevOps pages. It is free to use for personal and commercial purposes. You may not copy, modify, redistribute, reverse-engineer, or create derivative works based on this extension. This policy explains what data the extension accesses, how it is used, and what leaves your browser.

Data Stored Locally

The following values are saved to chrome.storage.local, stored exclusively on your device and never transmitted to any server operated by this extension:

  • Personal Access Token (PAT): used to authenticate calls to the Azure DevOps REST API. Never sent anywhere other than dev.azure.com or *.visualstudio.com.
  • AWS Bedrock Bearer Token: your ABSK token for AI refinement. Never sent anywhere other than bedrock-runtime.*.amazonaws.com.
  • Settings: toggles, AWS region, AI model ID. Stored locally only.

Data Sent to Azure DevOps

The extension calls the Azure DevOps REST API to:

  • Create a PR (title, description, work item links) when you click + PR
  • Fetch commits between branches to generate the PR description
  • Fetch branch refs and committer identity for ownership checks
  • Delete a branch ref when you confirm a branch deletion

These calls are made directly from your browser to Azure DevOps using your configured PAT or existing session cookies. No intermediate server is involved.

Data Sent to AWS Bedrock

When AI description generation is enabled and a PR is created, the extension sends to AWS Bedrock:

  • The selected commit messages
  • The PR title, source branch name, and target branch name
  • The template-generated draft description

No source code, file diffs, PAT tokens, API keys, or personal account information are included in the AI description request. When AI is disabled, no data is sent to any AI provider.

Data Sent by AI Remediate

When AI Remediate is triggered, the extension calls the ADO Pipelines API to start the configured fix pipeline. The following are passed as pipeline parameters:

  • The work item ID
  • The target repository name and target branch
  • Your PAT and Bedrock bearer token (as secret runtime variables — masked by ADO)

The pipeline itself (running on your ADO agents) calls AWS Bedrock with work item and code context to perform the fix. No data from the AI Remediate pipeline is sent to any server operated by this extension.

Data Not Collected

Azure DevOps Git Assistance does not collect, transmit, or store:

  • Usage analytics or telemetry
  • Browsing history
  • Source code, file contents, or repository metadata beyond commit messages
  • Any data from pages other than Azure DevOps

Third-Party Services

The only external services the extension may contact are Azure DevOps (always) and AWS Bedrock (only when AI is enabled). No analytics, advertising, or tracking services are used.

Data Deletion

Remove the extension from Chrome to delete all locally stored data. You can also clear the extension's storage via chrome://extensions → Azure DevOps Git Assistance → Clear storage.
