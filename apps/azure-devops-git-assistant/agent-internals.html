Phase Roles & Tool Access

IDLE
Start state. No tools. Transitions only to LOADING_SKILL.
LOADING_SKILL
Reads skills/work-item-fix/SKILL.md and injects it as the system prompt for all agent phases. No tools available.
INVESTIGATING
Fetch the work item, explore the repo, identify root cause and exact files/lines. Goal: smallest possible change. Budget: 50 iterations.

REPRODUCING bug only
Receives the full INVESTIGATING conversation as context — no need to re-fetch the work item. Finds the nearest test file, reads it, inserts a single failing test using replace_in_file (preferred) or apply_patch. Pre-fix run checks the test must fail; retries once with feedback if it passes. Continues regardless after one retry. Budget: 20 iter / attempt.
read_filelist_files search_codefind_references replace_in_file ✦apply_patch
PLANNING
Pure LLM synthesis — no tools. Compresses INVESTIGATING output into a compact self-contained fix plan. Always draws from investigationResult, never from REPRODUCING.
REMEDIATING
Apply patches. Only exact lines needed — no reformatting, no new files, no unrelated cleanup. Bug fixes must make the REPRODUCING test pass without deleting it. Re-entered on validation failure or critic reject. Tool errors logged to stderr and injected into retry context.
get_work_itemread_filelist_files search_codefind_references replace_in_file ✦apply_patch
PROVING security only non-fatal
Read-only dry-run. Agent reads patched files and reasons about whether the attack vector is closed — quoting specific lines and identifying remaining paths. apply_patch and replace_in_file are blocked. Does not affect ctx.appliedPatches or the validation hash. Failure does not block the fix. Budget: 20 iter.
get_work_itemread_filelist_files search_codefind_references
VALIDATING
FixValidator runs independently — never accessible to Claude. Checks: (1) patch applied, (2) non-empty files, (3) JSON/XML parseable, (4) output scan passes, (5) patch scope clean, (6) TEST_COMMAND exits 0 if set. On failure, tool errors from REMEDIATING are injected into the retry prompt.
read_filelist_files
CRITIC
Independent LLM call (no tools). Receives fix plan + unified diffs (git diff --cached --unified=5, captured at apply time, up to 8 000 chars). A reject always blocks PR — no bypass limit. Feedback injected into next REMEDIATING attempt.
CREATING_PR
Blocked if patch hash changed since validation. Pushes to ai-fix/wi-<id>-<ts>, creates PR, links work item.
create_pull_requestlink_work_item
COMPLETE
Terminal. PR created, work item linked, rich ADO comment posted.
FAILED / BUDGET_EXCEEDED / BLOCKED
Terminal error states. Report JSON + Markdown published as pipeline artifact.

Operation Fires in phases Notes
git add REPRODUCINGREMEDIATING Side-effect of apply_patch / replace_in_file after fs.writeFileSync (apply-patch.ts:90). Stages the file so the output scanner and diff capture can run. If staging fails, disk is restored and the tool returns an error. Claude passes only {path, content}.
git diff --cached REPRODUCINGREMEDIATING Run immediately after git add (--unified=5). Output stored in PatchRecord.unifiedDiff at apply time. The Critic always reads this snapshot — never a re-computed diff — so it reflects the exact state even if the file is patched again in a later retry.
git restore --staged REPRODUCINGREMEDIATING Rollback path only. Called when the output scanner rejects the staged diff — unstages the file and overwrites disk with originalContent. Never fires on a clean scan. Claude cannot trigger or suppress it.
ADO Pushes API CREATING_PR POST /_apis/git/repositories/{repo}/pushes — called by the orchestrator in pushPatchesToBranch after the patch hash is verified. Sends patchedContent as rawtext; ADO creates the commit server-side. Replaces git commit + git push entirely — no git credentials needed on the agent.

Security Guards

Guards scan tool inputs before execution. A block is a hard failure — no redact-and-continue. The error includes matchedText (≤80 chars) visible in pipeline logs.

base64Guard always on

Detects Base64-encoded payloads that could smuggle injection patterns past the regex guard.

llmGuard optional

Secondary LLM evaluator. Active when llmClient is in GuardOptions.

azurePromptShield optional

Calls Azure AI Content Safety prompt shield. Requires AZURE_CONTENT_SAFETY_ENDPOINT + AZURE_CONTENT_SAFETY_KEY.

Length guard removed. The 8 000-char limit blocked legitimate large work items.

Output scanner

Runs on git diff --cached after every apply_patch / replace_in_file. On failure the file is unstaged and restored — patch rolled back.

Critic Phase

Independent LLM call (no tools). Receives fix plan + unified diff hunks captured at apply time via git diff --cached --unified=5 — up to 8 000 chars per file, full coverage regardless of where in the file the change appears. A reject always blocks PR — no bypass limit.

DO evaluate

  • Does the fix address the root cause in the plan?
  • Are there logic errors, bypasses, or unintended side effects?
  • Does the change match acceptance criteria in the work item?
  • If a version number was replaced — does the old value still appear in patched content?
  • (Bug fixes only) Is a regression test present and does it cover the specific bug?

DO NOT reject based on

  • Whether a CVE exists in any external database (no internet access)
  • Whether a package version exists on NuGet / npm / PyPI
  • Whether a version bump is a breaking change
  • Any external fact not derivable from the provided text

PR Description — AI Generation

The + PR button generates an AI-refined description from commits and changed files.

  1. Fetch branch commits and changed files from diffs/commits API in parallel.
  2. Filter commits (merge commits optional per settings).
  3. Template generator builds structured draft.
  4. AI refinement receives draft + commit messages + changed file list — uses file paths to make bullets specific.
  5. Refined Markdown set as PR description on creation.
